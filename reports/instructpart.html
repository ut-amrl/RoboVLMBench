InstructPart

Finding the part of an object to act on: 600 photos, one target part each (paper). No official evaluation code is released; this protocol is ours.

What it tests

  • Task (600 questions): a task instruction that doesn't name the part, so the model must work out which part to use. E.g. “If I want to open the cabinet, which part in the picture should be used? Point to that part in the image.”
  • Part (600 questions): the same photos with the part named. E.g. “Point to the handle of the cabinet in the image.”

An answer is correct if its first point lands on the part's annotated mask.

% of answers whose first point lands on the part. For scale: a point at the image center scores 20.0, a random point 6.6 (parts cover a median 3.8% of the photo). With 600 questions per variant, a score is uncertain by up to ±4 points (95% interval). Time per question: from sending a question to receiving the whole answer (reasoning included), with questions sent one at a time and nothing else on the GPUs. Every image is sent as new, so the server can't reuse work from earlier questions on the same image, as for a robot whose next question comes with a new camera frame. Output tokens: median per question, reasoning included. Unusable answers: cut off at the token limit, unparsable, or failed (hover for which); they count as wrong.
