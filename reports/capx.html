CaP-X

Code as policy: the model writes Python that drives a simulated robot arm through CaP-X's perception and control functions; an episode succeeds if CaP-X's check finds the task done after the code has run. 1340 episodes per model.

What is run

  • Robosuite: 7 tasks (cube lifting, cube stack, cube restack, nut assembly, spill wipe, two arm lift, two arm handover). Variants: privileged. 20 trials per task.
  • LIBERO-PRO: 6 suites × 10 tasks (libero_goal_swap, libero_goal_task, libero_spatial_swap, libero_spatial_task, libero_object_swap, libero_object_task); swap: objects in other positions; task: a different task in the same scene. Variants: privileged, multiturn_privileged. 10 trials per task.

Variants (which CaP-X config: API and interaction):

  • privileged: single turn; the API reads object poses from the simulator (no perception)
  • multiturn_privileged: as privileged, but after its code runs the model sees the console output and may write new code, up to 10 times

Each trial starts from its own initial state (Robosuite: seed = trial number; LIBERO: the task's n-th initial state). Prompts, code extraction, execution and success checks are CaP-X's own; the model is queried with its own request settings (see Runs).
